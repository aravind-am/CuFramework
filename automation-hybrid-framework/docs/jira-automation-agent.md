# Jira Automation Agent

The Jira Automation Agent is a repo-local Python command-line tool that syncs Jira Cucumber test cases into this automation framework.

It is not an MCP server or a Codex skill. It is currently run manually from the `automation-hybrid-framework` folder.

## What It Does

The agent:

- Reads Jira issues marked with the `AutomationCandidate` label and `New` status.
- Uses Jira test cases whose test type is `Cucumber`.
- Reads the Jira Gherkin field and writes it directly to a Cucumber `.feature` file.
- Creates or updates a matching Java step-definition class.
- Shows a change plan before editing framework files.
- Applies changes only after confirmation.
- Writes an audit log for every approved run.

## Default Jira Query

By default, the agent uses:

```jql
labels = "AutomationCandidate" AND status = "New" ORDER BY updated DESC
```

You can pass a project key:

```powershell
python tools\jira_automation_agent.py --project-key QA
```

Or pass full JQL:

```powershell
python tools\jira_automation_agent.py --jql "project = QA AND labels = AutomationCandidate AND status = New AND 'Test Type' = Cucumber"
```

If your Jira test type field is not available in JQL, set `JIRA_TEST_TYPE_FIELD` and let the agent filter non-Cucumber issues after reading them.

## Required Jira Setup

Set these values in PowerShell before running against Jira:

```powershell
$env:JIRA_BASE_URL = "https://your-domain.atlassian.net"
$env:JIRA_EMAIL = "your.email@example.com"
$env:JIRA_API_TOKEN = "your-token"
```

Set the Jira custom field IDs or names used by your Jira test-management app:

```powershell
$env:JIRA_TEST_TYPE_FIELD = "customfield_12345"
$env:JIRA_GHERKIN_FIELD = "customfield_67890"
```

`JIRA_GHERKIN_FIELD` should point to the field that contains the Cucumber scenario or feature text.

## Generated Files

For each Jira issue, the agent maps files like this:

```text
src/test/resources/features/<jira-key>_<summary>.feature
src/test/java/stepdefinitions/<JiraKeySummary>Steps.java
```

Example:

```text
src/test/resources/features/qa-101_valid_user_can_log_in.feature
src/test/java/stepdefinitions/Qa101ValidUserCanLogInSteps.java
```

Generated files include an agent marker, such as:

```text
Generated by Jira Automation Agent
```

When Jira Gherkin changes, files with this marker can be updated by rerunning the agent. Files that do not look agent-generated are treated as manually owned and are not overwritten.

## Step Definition Behavior

By default, the generated Java step file contains pending methods for every Gherkin step in the Jira test case.

Use this option if you want to skip steps that already exist in the framework:

```powershell
python tools\jira_automation_agent.py --project-key QA --reuse-existing-steps
```

## Approval Prompt

Before changing files, the agent prints a plan:

```text
Pending framework changes
JQL: labels = "AutomationCandidate" AND status = "New" ORDER BY updated DESC
- update: src\test\resources\features\qa-101_valid_user_can_log_in.feature
  Jira: QA-101
  Reason: Sync generated Cucumber feature with the latest Jira Gherkin.
```

The agent applies changes only after you type `yes` or `y`. The answer is case-insensitive, so `Yes`, `YES`, and `Y` also work.

Any other answer aborts the run without changing framework files or writing an audit log.

## Audit Logs

Every approved run writes a log under:

```text
AIAudit/
```

Audit logs are named like:

```text
AIAudit/jira_automation_agent_YYYYMMDD_HHMMSS.log
```

Each log records:

- Timestamp
- Mode
- JQL
- Planned file changes
- Actual file results

## Dry Run

Preview the plan without changing files:

```powershell
python tools\jira_automation_agent.py --project-key QA --dry-run
```

Dry-run does not prompt, does not change framework files, and does not write an audit log.

## Offline Sample Run

Use the sample Jira issue without connecting to Jira:

```powershell
python tools\jira_automation_agent.py --sample-issue tools\sample_jira_issue.json --dry-run
```

Apply the sample after reviewing the prompt:

```powershell
python tools\jira_automation_agent.py --sample-issue tools\sample_jira_issue.json
```

## Notes

- Run commands from the `automation-hybrid-framework` folder.
- Keep the Jira Gherkin valid. If a `Then` step is intended, put it on its own line in Jira.
- The agent syncs generated files only. Manual test scripts remain protected unless they contain the agent marker.
